MCP Case Studies & Agent-Ready Infrastructure

Current design-system MCP practice is converging on a stack: structured contracts, routed context, skills, evals, and governance — not a single magic server.

MCP as a production surface

The frontier cases show MCP moving from a protocol curiosity into a maintained design-system surface. Figma exposes design context, variables, Code Connect mappings, library search, screenshots, assets, and remote canvas-write tools through its MCP server, while its official skills prescribe step-by-step workflows for implementing designs, creating design-system rules, and generating Figma libraries from code and tokens.1 GitHub Primer distributes @primer/mcp as a package for tokens, components, examples, patterns, and usage guidance, and a Primer Brand PR adds smoke tests and eval-dashboard work around brand-specific MCP output.6 Storybook exposes a running Storybook as an MCP endpoint where agents can query documentation, preview stories, and run tests.9

The implication is architectural: the design system is no longer only a website, Figma library, and npm package. It also has an agent-facing API surface that needs versioning, smoke tests, routing rules, and output design.

The emerging stack

Across cases, the durable pattern is not “add MCP.” It is a stack of complementary surfaces:

  • Structured contracts for deterministic facts: component props, variants, tokens, examples, and allowed values. Indeed's JSON benchmark, Primer's package, Storybook manifests, and Primitiv's contract all live here.2679
  • Layered guidance for judgment: spatial rhythm, composition, brand feel, accessibility expectations, implementation rules, and taste. Indeed's plugin architecture and Spotify's layered Encore workstream both point beyond component lookup.38
  • Skills and routing rules for process: Figma's official skills, Miro's icon/token and wrap-up skills, and Storybook's recommended AGENTS.md/CLAUDE.md instructions tell agents when and how to use the system.149
  • Validation and evals for trust: Indeed's format benchmark, Primer Brand eval work, Spotify's reported visual/lint/similarity framework, Storybook's test loop, and Primitiv's CI verification all make agent output measurable.26897

Perspectives: retrieval vs. reconciliation

The retrieval camp treats the main problem as access: expose the right docs, tokens, components, variables, stories, and examples so agents stop guessing. Figma, Primer, Storybook, NYSDS, and Miro all strengthen this position by making previously human-oriented system knowledge directly queryable.16954

The reconciliation camp argues that access is insufficient when Figma, code, Storybook, docs, and token files disagree. Primitiv's thesis — “Retrieval gives you data. Reconciliation gives you truth.” — makes conflict resolution the missing layer before MCP retrieval.7 Indeed's deprecated active-card example supports the same warning from another angle: if documentation contains stale instruction, the agent's faithful compliance amplifies the system's truth debt.3

Position: retrieval is the first maturity threshold; reconciliation is the second. A design-system MCP that retrieves stale or contradictory data can become an accelerant for drift, while a reconciled contract can become a governance artifact.

Perspectives: MCP vs. skills, plugins, and rules

MCP is best for stable, shared, queryable capabilities: get a component, find a token, retrieve docs, inspect violations, preview stories. Skills, plugins, and root rules are better for task choreography: when to call tools, which references to load, how to perform wrap-up checks, and what process gates must not be skipped.1349 Treating these as substitutes is a category error; the frontier systems combine them.

What these cases prove — and do not prove

They prove that design systems are becoming machine-facing infrastructure: MCP packages, token filters, eval harnesses, CI checks, skills, and layered context libraries are now part of the field's operating model. They do not prove that any single MCP server guarantees brand-quality UI. The strongest cases still depend on clean metadata, negative constraints, explicit routing, tests, human checkpoints, and source-of-truth hygiene.1347
