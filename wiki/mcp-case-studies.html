MCP Case Studies & Agent-Ready Infrastructure

Selected 2026 examples suggest a recurring stack—structured contracts, routed context, skills, evals, and governance—while their evidence ranges from public capabilities to unverified internal outcomes.

MCP as a production surface

Public documentation establishes Figma's MCP toolset, the shipped Primer React package, and Storybook's preview React MCP.169 Separately, an open Primer Brand PR describes proposed brand-specific tools, smoke tests, and an eval dashboard; that in-flight work is not equivalent to a shipped capability.6

Position: where a design system exposes an agent-facing API, teams should treat it as a maintained product surface—with versioning, tests, routing rules, and deliberate output design—rather than assume MCP itself supplies those qualities.

Evidence grades used on this page

  • Public capability: documented in an official public repository, merged change, release, or product documentation as of the source's July 2026 retrieval date.
  • Reported internal practice: described by a practitioner, conference recap, or secondary case report but not independently verified in this corpus.
  • Reported outcome or benchmark: a quantitative or qualitative result reported by the case, scoped to its own evaluation design and not reproduced here.

Open-source existence establishes that an interface or tool is available; it does not establish organizational adoption, production reliability, or improved outcomes.

The emerging stack

Across this selected case set, the recurring pattern is not merely “add MCP.” It is a stack of complementary surfaces:

  • Structured representations of props, variants, tokens, examples, and allowed values. Indeed is a reported internal implementation, Primer and Storybook are public capabilities, and Primitiv is a documented project claim.2679
  • Layered guidance for judgment: the reported Indeed and Spotify cases describe spatial, compositional, brand, and implementation context beyond component lookup.38
  • Skills and routing rules for process: Figma and Storybook publicly document workflow guidance, while Miro's icon/token and wrap-up skills are reported internal practice.149
  • Validation and evals for trust: the set combines Indeed's reported benchmark, in-flight Primer Brand eval work, Spotify's reported framework, Storybook's documented test loop, and Primitiv's documented CI option.26897

Perspectives: retrieval vs. reconciliation

The retrieval camp treats the main problem as access: expose the right docs, tokens, components, variables, stories, and examples so agents infer less. Public Figma, Primer, Storybook, and NYSDS interfaces—and the reported Miro Aura practice—illustrate this position at different evidence levels.16954

The reconciliation camp argues that access is insufficient when Figma, code, Storybook, docs, and token files disagree. Primitiv's documentation makes conflict resolution a layer before retrieval.7 Indeed's reported stale-documentation example illustrates the same risk without validating Primitiv's particular approach.3

Provisional position: retrieval may be sufficient while sources agree; explicit reconciliation becomes important when they conflict. The corpus does not establish reconciliation as a universal maturity sequence or prove that a generated contract is automatically true.

Perspectives: MCP vs. skills, plugins, and rules

These cases suggest a useful division: MCP for shared queryable capabilities, and skills, plugins, or rules for task choreography—when to call tools, which references to load, and which process gates to preserve.1349 Several examples combine them, but the evidence does not establish this as the only viable architecture.

What these cases demonstrate—and leave unproven

Public artifacts demonstrate that agent-facing packages, token filters, preview/test loops, and CI affordances exist. Reported internal cases indicate experimentation with layered context, routing, and evals. Together they provide evidence of an emerging practice, but not field-wide adoption or reliable brand-quality outcomes. No single MCP server guarantees fidelity; the cases repeatedly pair interfaces with metadata, negative constraints, routing, tests, human checkpoints, and source-of-truth hygiene.1347
