Modular & Parametric Scales

Generating typography, spacing, and density from base values and ratios — so the system scales by math instead of by hand.

The origin problem

Nate Baldwin's case study starts concretely: his team at Intuit supported button heights of 24/36/48px on an 8-pixel grid. When marketing needed larger buttons, the grid mechanically produced 56 and 64px — but those increments weren't proportional, which is how rigid pixel grids accumulate inconsistency.1

Ditch the pixel grid for modular scales

Baldwin explicitly criticizes rigid pixel grids as non-proportional and prone to inconsistency, advocating modular scales — a base value and a ratio — to generate values instead.1 The same modular formula can drive spacing as well as type, keeping their visual relationships proportional without requiring both scales to use the same units or respond to the same inputs.1

Responsive typography

Baldwin uses conditional ratios and base font sizes that adapt to viewport width, then converts generated text sizes to rem. Because rem follows the browser's root font size, a user's font-size preference changes the type scale while preserving its proportional hierarchy.1

Accessibility constraints on fluid scales

Viewport-responsive scaling and user-controlled text scaling are separate dimensions. Baldwin's model lets both typography and spacing respond to the viewport, but only text follows the user's preferred font size: text uses rem, while spacing remains in px so the interface does not simply enlarge every spatial value along with the type.1

This distinction also bounds the fluid-scaling recommendation. Utopia can generate CSS clamp() functions that interpolate between viewport sizes, but Baldwin warns that some clamp()-based formulas can interfere with users' ability to scale text. A mathematically fluid scale therefore still requires accessibility testing and may need correction rather than unconditional adoption.1

Size vs. density

A key distinction Baldwin draws:1

  • Size affects the overall scale of an element, including its text.
  • Density affects only the internal padding of a component.

Separating these dimensions means a density change doesn't break content hierarchy. Padding in component archetypes is defined via relative indices (e.g., −4, −1, 0, 1) rather than hard-coded pixels, making it responsive and adjustable via the scale.

Tooling

Baldwin points to parametric tools: Proportio (his own open-source tool for proportional type/spacing/component systems), Utopia.fyi (CSS clamp() for fluid scaling across viewports), and Token Studio (graph-based, editable representations of system structure). His Utopia recommendation carries the accessibility caveat above; the tool does not make every generated formula safe by default.1

Perspectives: mathematical consistency vs. human override

  • Parametric consistency: constants and ratios let a change propagate while preserving hierarchy, avoiding the unclear relative differences produced by a linear pixel grid.1
  • User-controlled scaling: proportional viewport behavior is not the same as accessible text resizing. In Baldwin's model, rem-based text follows user preference while pixel-based spacing deliberately does not.1
  • Optical and accessibility correction: a generated value can be mathematically consistent yet still need adjustment for legibility, optical balance, or user override. Baldwin's clamp() warning is the decisive counterweight to treating fluid generation as self-validating.1

Wiki position: parameterization is a powerful default for generating coherent relationships, not a license to remove human judgment. Preserve the formula where it helps the system change; preserve user control and tested corrections where the formula conflicts with use. This connects to the systems-thinking principles of encapsulation and archetypes, and its outputs can feed the token architecture.
