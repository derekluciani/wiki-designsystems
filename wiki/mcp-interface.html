MCP & the Machine-Readable Interface

The Model Context Protocol is the connective tissue between a design system and an agent — and how you structure what it exposes makes or breaks accuracy and cost.

What MCP does

The Model Context Protocol is a standard for feeding AI tools the real, structured data behind a design — its intent, tokens, variables, and components — rather than letting them guess from screenshots.1 Figma's Dev Mode MCP server turns a Figma file into an interactive context layer that AI coding tools can query: "X-ray vision" for spacing, color, and component logic, enabling higher-fidelity code generation, especially when the system is cleanly structured.1

From interface to infrastructure

Recent public and practitioner cases show MCP becoming a maintained production surface for design systems rather than a one-off bridge. Figma exposes design context, variable definitions, Code Connect maps, library search, screenshots, asset transfer, and remote write operations; Primer distributes @primer/mcp as an installable design-system package; Storybook exposes a running Storybook at an MCP endpoint with documentation, preview, and testing toolsets.61114 See MCP Case Studies & Agent-Ready Infrastructure.

Storybook MCP as connective tissue

In the agentic-2026 session, the Storybook MCP server is demonstrated as the connective tissue that exposes design-system components, APIs, and interaction tests to AI agents in a structured, token-optimized format.2 Storybook's public MCP server operationalizes that idea: agents can query docs, generate or update stories, preview story output, and run Storybook tests, including accessibility checks when configured.14 The system's components, not generic web knowledge, become the agent's vocabulary.

Component specs as MCP payloads

Curtis's components-as-data argument points to what MCP should expose next: not just component names and prose docs, but compact structured specs that describe props, anatomy, defaults, bindings, variants, slots, and constraints. This moves agents from interpreting rendered artifacts to querying component intent as data.5

JSON for MCP, Markdown for LLM

The most important structural lesson: early attempts dumped Markdown docs into an MCP server, causing high token usage, hallucinations, and poor adherence to component contracts. Encoding component APIs and variants as structured JSON instead reduced token usage by ~80% (per Indeed's case study) and dramatically improved accuracy and cost.3

Indeed's newer benchmark sharpens this from rule of thumb into an evaluation claim: a reported 8-configuration, 1,056-prompt comparison found JSON equal or better than hybrid Markdown+JSON for structured component metadata while using far fewer tokens; Markdown remained useful for natural-language rules and instructions.7 NYSDS reaches the same split at token-tool scale by returning raw JSON for token lookup while moving theme guidance into Markdown guide content.10

The emergent pattern is "JSON for MCP, Markdown for LLM": machine-readable structured data (props, variants, allowed values) as JSON schemas; human-oriented guidance and interaction rules as Markdown. Metadata stays under source control with a pipeline that converts MDX/Storybook docs into MCP-readable JSON whenever components change.3 Atlassian implemented this pattern by distributing modular instruction blocks (types, examples, guidelines) to their MCP server (@atlaskit/ads-mcp) and other agents using a structured offerings.json schema (see Agentic Content & Prototyping Templates).

Expose foundations, not just components

A specific failure mode: MCP interfaces that reveal components but omit foundations (spacing, typography) force agents to guess and break brand consistency.3 Indeed's progressive-context work reports exactly this failure: component retrieval worked, but prototypes still drifted on typography hierarchy, spacing, color usage, icon conventions, and brand feel until foundations and recipes were loaded at the right time.8 Spotify's reported Encore work reaches a similar conclusion architecturally by separating foundations, component style, and component behavior to reduce context burden for humans and machines.13 This is the practical cash-value of the tokens-as-API idea — the foundation layer must be machine-visible too.

Output shaping is governance

An MCP response is not neutral documentation; it steers model behavior. NYSDS deliberately defaults token search to recommended semantic tokens, excludes primitive palette ramps that agents should not use directly, and drops cssValue from discovery responses to discourage primitive-reference misuse.10 Miro's Aura work points to the same principle for icons and tokens: add visual descriptions, use cases, categories, and explicit “do not use” constraints when names alone are not machine-usable intent.9

Retrieval is not reconciliation

MCP can retrieve design-system data, but it does not automatically decide which source is true when Figma, code, Storybook, docs, and token files disagree. Primitiv makes this a first-class layer: scan sources, reconcile conflicts, write a machine-readable contract, then serve context, conflicts, inferred rules, and violations through MCP.12 This reframes the mature MCP interface as not merely “how agents access docs,” but “how agents access reconciled system truth.”

Structured queries and APIs

The concept of exposing system schemas programmatically is not new; Shopify's Polaris design system previously pioneered this by offering a GraphQL API to expose components, tokens, pages, and examples directly to consumers.4 In an agentic workflow, this query-based structure becomes the interface protocol. By querying the design system as a structured database or knowledge graph rather than traversing human docs, agents can programmatically extract precise context (e.g., retrieving only components matching icons AND onboarding), optimizing performance and accuracy.4 See Design Systems as Knowledge Graphs.

Perspectives: structured data vs. prose

The corpus is unusually unanimous here: machine interfaces want structure, humans want prose, and conflating them is the original sin of design-system MCP work.3 The Figma Dev Mode MCP and Storybook MCP are both instances of the same move — give the agent the structured truth (tokens, variants, tests) rather than a rendered picture or a wall of docs.12 See AI-Assisted Authoring for MCP in a real authoring loop.
